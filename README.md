**Контрольная работа №4:** «JavaScript: интерактивность, DOM, события, формы и валидация».
Дисциплина: «Фронтенд и бэкенд разработка». **Студент:** Филиппов К.А., **группа:** ЭФБО-13-25.

Основа — `kr3-responsive-shop`: сохранены оформление магазина, адаптивная сетка,
навигация, изображения с `srcset`, skip-link и доступное модальное окно.
КР3 не изменена. КР4 находится в самостоятельном проекте `kr4-js-shop`.

**Публикация:** проект подготовлен для отдельного репозитория GitHub и GitHub Pages.
Ссылки будут добавлены после публикации. Файл `.nojekyll` отключает обработку Jekyll:
HTML, CSS, JavaScript и изображения публикуются напрямую из корня ветки `main`.

## Запуск

Откройте `index.html` или `catalog.html` в современном браузере.
Для самого сайта не нужны npm, сборка, интернет или сервер: используются обычные
скрипты с `defer`, а не модули и `fetch`.

Для стабильного общего `localStorage` при переходах между страницами рекомендуется
локальный HTTP-сервер. Из папки `kr4-js-shop`:

```powershell
python -m http.server 8004 --bind 127.0.0.1
```

Затем откройте [магазин](http://127.0.0.1:8004/) или
[каталог](http://127.0.0.1:8004/catalog.html). Остановка сервера — `Ctrl+C`.
Адрес, порт и способ открытия должны оставаться одинаковыми: хранилище привязано
к origin. Поведение `localStorage` для `file://` зависит от браузера.

## JavaScript-файлы

- `data.js` — массив `products`, словарь категорий, форматирование рублей и
  небольшие DOM-функции. `Shop.element()` использует `createElement`, `classList`
  и `textContent`, `Shop.notify()` выводит уведомление на страницу.
- `catalog.js` — генерация карточек, поиск, фильтрация, сортировка, счётчик,
  пустое состояние, популярные товары и подробные сведения обо всех моделях.
- `cart.js` — добавление, удаление, изменение количества, итог через `reduce`,
  промокод, чтение и сохранение состояния, синхронизация вкладок.
- `modal.js` — окно заявки для выбранной модели, ссылка на форму с её id,
  удержание фокуса, закрытие и возврат фокуса к вызвавшей кнопке.
- `validation.js` — список моделей в заявке, состав заказа, проверка обеих форм,
  сообщения у полей, имитация отправки, блокировка повторной отправки и очистка.
- `main.js` — общая инициализация. Каждый компонент проверяет наличие своих
  элементов, поэтому одинаковый набор файлов подключён на всех страницах.

Порядок подключения: `data → cart → catalog → modal → validation → main`.
Общие методы доступны через `window.Shop`; внутреннее состояние компонентов
закрыто внутри функций. Фреймворки и библиотеки для работы сайта не используются.

## Массив товаров

В `js/data.js` находятся **9 товаров** с одинаковыми свойствами:

| Свойство | Содержание |
| --- | --- |
| `id` | Уникальное целое число |
| `title` | Название модели |
| `category` | `home`, `work` или `portable` — совпадает с фильтром |
| `price` | Цена числом в рублях |
| `isAvailable` | Наличие: `true` или `false` |
| `slug` | Якорь на странице товаров |
| `image` | Имя локального изображения без расширения |
| `description` | Описание модели |
| `height`, `power`, `supply` | Высота, мощность и питание |
| `badge` | Текст бейджа либо пустая строка |

В каждой категории по три модели. Семь доступны, две ожидают поступления.
Дополнительные модели — учебные варианты трёх исходных серий; они используют
изображения соответствующих серий из КР3. Цены и характеристики демонстрационные.

## Каталог

Карточки создаются из массива через `createElement()` и добавляются через `append()`.
Перед обновлением используется `replaceChildren()`. В HTML нет готового списка карточек.

Поиск работает по части `title` на событии `input`, без учёта регистра и пробелов
по краям запроса. Фильтр категории и флажок «Только в наличии» работают на `change`.
Поиск, категория и наличие применяются одновременно через `filter()`.

Сортировка поддерживает возрастание и убывание цены, русское название через
`localeCompare('ru')` и исходный порядок. `sort()` применяется к копии массива,
поэтому исходные данные сохраняют порядок. Отображается количество результатов.
Если совпадений нет, появляются объяснение и кнопка сброса всех фильтров.

## Формы

В форме заявки проверяются:

- имя после `trim()` — от 2 до 50 символов;
- e-mail — адрес с именем, `@` и доменом с точкой, дополнительно HTML validity;
- телефон — российский номер с `+7` или `8` и ещё 10 цифрами;
  разрешены пробелы, скобки и дефисы;
- выбор доступного товара либо непустой корзины;
- согласие на обработку данных; комментарий необязателен, до 300 символов.

Форма обратной связи проверяет имя, e-mail, вопрос от 10 до 500 символов и согласие.
Ошибки выводятся рядом с полями, связываются через `aria-describedby`, поля получают
`aria-invalid`, а фокус переходит к первой ошибке. `novalidate` позволяет показать
собственные сообщения в DOM. После исправления подсветка соответствующей ошибки
обновляется на `input` и `change`.

После корректного `submit` на 650 мс показывается состояние подготовки, элементы
формы блокируются. Затем форма очищается и появляется итоговое сообщение.
В заявке отображается выбранная модель либо состав корзины с учётом скидки.
Корзина после имитации сохраняется: реального заказа нет. Проверка клиентская,
сетевые запросы отсутствуют, контактные данные не записываются в хранилище.

## Безопасный вывод и события

Названия, описания, уведомления, ошибки и имя из формы выводятся через `textContent`.
`innerHTML`, `outerHTML`, `insertAdjacentHTML`, `eval` и `alert()` не используются.
Даже введённый HTML отображается как текст.

Из `localStorage` принимаются только известные доступные id и положительное целое
количество, не более 99 штук; повторяющиеся id удаляются, посторонние свойства
не используются. Цена всегда берётся из `data.js`, а не из хранилища.
Повреждённый JSON не прерывает инициализацию. При запрете хранилища корзина работает
в памяти текущей страницы, а ограничение сохранения явно показывается пользователю.

Все обработчики подключены через `addEventListener()` для `click`, `input`, `change`,
`submit`, `reset`, `keydown`, `close`, `storage` и `hashchange`. Inline-обработчиков нет.
Кнопки динамических карточек обслуживаются делегированием `click` на документе:
`closest()` находит кнопку, `data-*` передаёт id и действие.

## Самостоятельные доработки

- Корзина: добавление с главной, из каталога и со страницы товаров, удаление,
  изменение количества, очистка, пустое состояние и общий счётчик в навигации.
- Расчёт `price × quantity` через `reduce()`, пересчёт суммы при каждом изменении.
- Промокод **SVET10**: скидка 10%, округление до целого рубля; неправильный код
  снимает скидку, повторное применение не суммирует её.
- Сохранение корзины и промокода в `localStorage`, проверка восстановленных
  данных и обновление других вкладок через событие `storage`.
- Единый сценарий «каталог → корзина → заявка», предварительный выбор модели
  из модального окна, состав заявки и итог с учётом скидки.
- Проверка обеих форм, ошибки у полей, состояние подготовки и безопасное
  сообщение с именем пользователя после имитации отправки.
- Фильтр наличия, недоступные кнопки отсутствующих товаров, бейджи и кнопка
  восстановления полного каталога в пустом состоянии.
- Доступный `dialog`: Tab/Shift+Tab, Escape и возврат фокуса.

## Проверка и сценарий защиты

1. Откройте каталог: девять карточек, счётчик «9 из 9».
2. Введите `куп`, затем `КУПОЛ`: поиск без учёта регистра находит три модели.
3. Выберите «Для работы» при запросе «Купол»: появляется пустое состояние.
   Нажмите «Показать весь каталог»: фильтры и поиск сбросятся.
4. Проверьте каждую категорию, наличие, обе сортировки цены и сортировку названий.
   Верните «По умолчанию»: исходный порядок восстановится.
5. Добавьте «Купол» дважды и «Линию» один раз: счётчик 3, сумма **24 200 ₽**.
   Примените `SVET10`: скидка **2 420 ₽**, итог **21 780 ₽**.
6. Перезагрузите страницу: состав и скидка сохраняются. Измените количество,
   удалите товар; затем проверьте очистку и пустую корзину.
7. Перейдите из непустой корзины к заявке: выбраны все товары, виден состав.
   Отправьте пустую форму, проверьте ошибки. Попробуйте неверные e-mail и телефон.
8. Заполните форму вымышленными данными, например `Тест`, `test@example.com`,
   `+7 (999) 123-45-67`, выберите товар, подтвердите согласие. Проверьте состояние
   подготовки, сообщение об успехе и очистку формы.
9. Откройте «Товары», вызовите заявку для «Линия Про». Проверьте Tab/Shift+Tab,
   Escape, возврат фокуса и выбор нужной модели после перехода к форме.
10. Проверьте форму обратной связи и Console на всех шести страницах.
